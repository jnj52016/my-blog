# 前后端项目部署学习 TODO

目标：

- 明白部署不是项目写完后的最后一步，而是从项目设计时就要考虑的运行方式
- 能把 React / Vite 前端、NestJS 后端和 PostgreSQL 数据库部署到服务器
- 能处理域名、HTTPS、环境变量、跨域、数据库迁移、日志、备份和回滚
- 上线后出现问题时，知道先检查哪里
- 最终形成一份以后每个项目都能复用的部署清单

---

## 一、先建立完整认识

一个完整项目上线后，大致是这样工作的：

```text
用户浏览器
    ↓ HTTPS
域名 / DNS
    ↓
Nginx 或云平台入口
    ├── /        → 前端静态文件
    └── /api     → NestJS 后端
                        ↓
                    PostgreSQL
```

同时还需要：

- 环境变量和密钥
- 数据库迁移
- 日志和错误监控
- 数据库备份
- 自动部署或明确的手动部署流程
- 出错后的回滚办法

## 二、开发前就要决定的事情

### 2.1 选择最小可用部署方案

第一个完整项目先使用简单方案：

- 一台 Linux 云服务器
- Nginx 托管前端并反向代理后端
- NestJS 以 Node.js 进程或 Docker 容器运行
- PostgreSQL 优先使用云数据库；学习阶段也可以先部署在同一台服务器
- 图片和大文件优先放对象存储，不存进应用容器

暂时不要一开始就学习：

- Kubernetes
- 多机集群
- 服务网格
- 复杂微服务

- [ ] 决定前端、后端、数据库分别部署在哪里
- [ ] 决定使用 Docker，还是先用 Node.js + 进程管理器
- [ ] 记录服务器地区、系统版本、配置和续费日期

### 2.2 统一域名和接口路径

推荐让前端和接口共用一个主域名：

```text
https://example.com       前端
https://example.com/api   后端接口
```

这样通常比使用两个域名更容易处理 Cookie 和跨域问题。

## 十、设计一次可靠的发布流程

推荐顺序：

```text
检查代码和测试
    ↓
构建固定版本
    ↓
备份数据库
    ↓
执行兼容性迁移
    ↓
发布后端和前端
    ↓
健康检查
    ↓
关键功能冒烟测试
    ↓
观察日志和指标
```

### 12.2 固定排障顺序

出现问题时，按请求链路逐层检查：

```text
DNS 是否正确
→ HTTPS 是否正常
→ Nginx 是否正常
→ 前端资源是否正常
→ 后端进程是否正常
→ 健康检查是否正常
→ 环境变量是否正确
→ 数据库和第三方服务是否正常
→ 日志中最早出现的异常是什么
```
