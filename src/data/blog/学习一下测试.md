# 第二阶段：学会设计“测试情况”

## 4. 学正常情况和边界情况

例如：

`calculatePrice(price, quantity)`

需要考虑：

- [ ] 正常价格

- [ ] 价格为 0
- [ ] 边界值
- [ ] 非法参数（如果业务需要处理）

- [ ] Happy Path：正常流程

目标：

# 第三阶段：Mock

## 5. 理解 Mock 是什么

先理解：

真实代码可能依赖：

`业务函数 → API → 数据库`

测试时不一定真的请求服务器。

所以可以：

`业务函数 → 假 API`

学习：

- [ ] `vi.fn()`
- [ ] `vi.mock()`
- [ ] `mockReturnValue`
- [ ] `mockResolvedValue`
- [ ] `mockRejectedValue`

目标：

知道什么时候应该 Mock，什么时候不应该 Mock。

## 12. 用 OpenAPI 帮助测试

这是非常适合你的部分。

检查：

- [ ] Status Code 是否符合 OpenAPI

- [ ] enum 是否合法

例如你之前遇到：

这本身就是测试发现的问题。

# 第十二阶段：学习 AI 时代的测试方式

## 15. 学会让 AI 帮你写测试，但自己负责测试设计

以后工作流程：

`AI 写功能`
↓
`你分析风险`
↓
`让 AI 补测试`
↓
`运行测试`
↓
`测试失败`
↓
`定位 Bug`
↓
`修复`
↓
`重新测试`

重点不是：

> 自己手打一大堆测试代码

而是：

> 你知道应该测试什么。
