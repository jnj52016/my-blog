# 测试快速上手 TODO

目标：能看懂项目测试、能运行它们，并能在 AI 写完关键功能后让 AI 补上合适的测试。

## 30 分钟核心路径

### 1. 看懂一份 Vitest 测试
- [x] 理解测试是“输入 → 执行 → 验证结果”
- [x] 理解 Arrange / Act / Assert
- [x] 看懂 `describe`、`it` 和 `expect`
- [x] 看懂 `toBe(true)`：结果必须严格等于 `true`

记住：测试通过表示“当前代码符合这条预期”；测试失败表示“代码或预期中至少有一个不对”。

### 2. 会运行测试
- [x] 在项目中运行全部测试：`pnpm test`
- [x] 知道红色失败信息通常会指出失败的测试和实际结果

### 3. 知道该测什么
- [x] 优先测业务规则、权限、金额、状态转换和异常处理
- [x] 每个关键规则至少覆盖：正常情况、边界情况、错误情况

例：`isAdult(age)` 至少关注 `18`、`17`，以及业务是否允许负数或空值。

### 4. 认识三种最常见测试
- [x] 单元测试：一个函数或一个 Service 的规则是否正确（Vitest / Jest）
- [x] 组件测试：页面是否展示正确、点击后是否变化（React Testing Library）
- [x] 接口 / E2E 测试：请求或完整用户流程是否成功（Supertest / Playwright）

不用现在学完它们。项目遇到对应问题时，再查对应工具即可。

### 5. 日常实战工作流
- [ ] AI 写完一个关键功能后，先列出正常、边界、错误三类情况
- [ ] 让 AI 为这些情况补测试
- [ ] 运行测试；失败时先看“期望值”和“实际值”
- [ ] 修改代码后重新运行测试

## 以后按需查阅

- Mock：测试时用假的 API、数据库或函数，避免依赖真实外部服务。
- 异步页面：关注 loading、成功、失败三种状态。
- NestJS：优先测 Service；Controller 和数据库联调放到接口测试。
- OpenAPI：用状态码、字段和错误结构判断接口是否符合约定。
- Playwright：只给登录、支付、发布等关键流程写少量 E2E。

## 完成标准

- [ ] 能运行项目的测试并看懂结果
- [ ] 知道关键功能该覆盖哪些情况
- [ ] 能让 AI 写测试、自己判断测试是否覆盖了风险
